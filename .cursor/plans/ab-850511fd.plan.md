# Webhook „pagehide” dla Porzuconych Koszyków – Plan zmian

1. Nowy endpoint: `POST /api/abandoned-carts/webhook`

   - Lokalizacja: `src/app/api/abandoned-carts/webhook/route.ts`
   - Cel: przyjęcie payloadu z `sendBeacon`, walidacja Zod, upsert do `abandoned_carts`, NATYCHMIASTOWE utworzenie deala w Bitrix24, aktualizacja rekordu (`bitrix_deal_id`, opcjonalnie `status: 'exported'`).

2. Walidacja

   - Użyj istniejącego `abandonedCartUpsertInputSchema`; dodaj pole `event?: 'pagehide' | 'beforeunload' | 'heartbeat'` (opcjonalne, do logów/metryk).
   - Warunki jak dotychczas: `stage === 'checkout_step2'` oraz `cartHasItems === true`.

3. Logika endpointu webhook

   - Krok A: parse body → walidacja Zod → oblicz `expireAt = now + 15min` (dla spójności TTL).
   - Krok B: upsert: jeśli istnieje `pending` dla `session_id` bez `bitrix_deal_id` → `update`, inaczej `insert` (jak w `/api/abandoned-carts`).
   - Krok C: NATYCHMIAST po upsercie pobierz pełny rekord i wywołaj `dealService.createDealForAbandonedCart(record)`.
   - Krok D: Po sukcesie: `update abandoned_carts` ustawiając `bitrix_deal_id` (i ewentualnie `status: 'exported'`).
   - Odpowiedź JSON: `{ success: true, dealId, recordId }`/błąd 4xx/5xx.

4. Frontend: aktualizacja hooka

   - Plik: `src/hooks/useAbandonedCartHeartbeat.ts`.
   - Zostaw bez zmian cykliczny `fetch('/api/abandoned-carts')`.
   - W `onPageHide`/`beforeunload` wysyłaj `sendBeacon` na nowy endpoint: `/api/abandoned-carts/webhook` (ten sam payload + `event: 'pagehide'`).

5. Cron – pozostaje jako fallback

   - Bez zmian w `src/app/api/abandoned-carts/cron/route.ts` (przetwarza tylko rekordy bez `bitrix_deal_id`).

6. Testy (Vitest + RTK gdzie ma sens)

   - `src/app/api/abandoned-carts/__tests__/webhook.test.ts`: scenariusze
     - poprawny payload → upsert → `crm.deal.add` wywołany → rekord ma `bitrix_deal_id`.
     - duplikat (ten sam `sessionId`) → update + idempotentny eksport (mock dealService).
     - niepoprawny payload/stage → 400.

7. Dokumentacja

   - Krótka sekcja w README: przepływ pagehide → webhook (payload, warunki, odpowiedzi).

### Kluczowe fragmenty (skrót)

- Endpoint webhook – szkic:
```ts
export async function POST(request: NextRequest) {
  const input = abandonedCartUpsertInputSchema.extend({ event: z.enum(['pagehide','beforeunload','heartbeat']).optional() }).parse(await request.json());
  if (input.stage !== 'checkout_step2' || !input.cartHasItems) return NextResponse.json({ success:false, error:'Not eligible' }, { status:400 });

  const expireAt = new Date(Date.now() + 15*60*1000).toISOString();
  const existing = await supabase.from('abandoned_carts').select('id').eq('session_id', input.sessionId).eq('status','pending').is('bitrix_deal_id', null).limit(1).maybeSingle();
  const record = existing ? (await update(..., { expire_at: expireAt, ... })).data : (await insert(..., { expire_at: expireAt, ... })).data;

  const created = await dealService.createDealForAbandonedCart(record as AbandonedCartRecord);
  if (!created.success) return NextResponse.json({ success:false, error: created.error }, { status:500 });
  await supabase.from('abandoned_carts').update({ bitrix_deal_id: created.id, status: 'exported' }).eq('id', record.id);
  return NextResponse.json({ success:true, dealId: created.id, recordId: record.id });
}
```
